ORION FINANCE v0.1 — QA
=======================

DIREÇÃO DE PRODUTO
------------------
- Recomeço real: banco local novo e backend novo.
- Nenhuma importação/conversão do histórico 0.14.x.
- Interface mobile-first high-end, com 4 áreas: Mov. | Início | Planejar | Mais.
- Premium, Radar, Evolução, XP, medalhas e gamificação explícita não fazem parte da v0.1.
- Saúde financeira aparece apenas como indicador discreto no card de saldo.

VALIDAÇÕES EXECUTADAS
---------------------
1. JavaScript
   - mobile/orion.js: node --check OK.
   - mobile/service-worker.js: node --check OK.
   - Apps Script v0.1: validação sintática via node --check OK.

2. HTML / estrutura
   - 116 IDs únicos no mobile/index.html.
   - 0 IDs duplicados.
   - Referências principais de arquivos locais verificadas.
   - Manifest JSON válido.

3. PWA / offline
   - Service Worker sem dependências externas.
   - Shell pré-cacheado: HTML, CSS, JS, manifest e ícones.
   - Navegação possui fallback somente para documento HTML.
   - JS/CSS não recebem index.html como fallback.
   - updateViaCache: none no registro do Service Worker.
   - IndexedDB é carregado antes da sincronização.
   - App continua operando localmente sem URL do Apps Script.

4. Reinício real
   - Banco novo: orion_finance_v01.
   - O bootstrap solicita exclusão do banco legado conhecido orion_finance_2.
   - Caches antigos orion-mobile-* são removidos.
   - Não há rotina de importação histórica.

5. Campo monetário
   Testes:
   1      -> 0,01
   12     -> 0,12
   123    -> 1,23
   1234   -> 12,34
   123456 -> 1.234,56
   - inputmode=numeric.
   - Campos usam 16px ou mais para evitar zoom automático do iOS.

6. Caju
   - Ao selecionar conta/instituição contendo "Caju", pagamento passa para Crédito.
   - Não existe lógica de fatura/cartão no modelo v0.1 para essa conta.
   - O valor reduz diretamente o saldo físico da conta.

7. Transferências
   - Origem diminui e destino aumenta.
   - Transferência não entra em Entradas/Saídas/Resultado do mês.
   - Teste de aritmética executado com sucesso.

8. Perfis / alocações
   - Perfil João criado na primeira execução.
   - Perfis dependentes/patrimônio podem ser criados.
   - Cofrinho/objetivo pode pertencer a outro perfil e usar uma conta física existente.
   - Aporte é uma alocação patrimonial, não receita/saída bancária falsa.
   - Aporte não pode exceder o saldo ainda não alocado da conta física.
   - Perfil principal desconta valores de perfis gerenciados do patrimônio próprio.

9. Movimentações
   - Saída, Entrada, Transferência e Rendimento.
   - Edição mantém a mesma ID do movimento.
   - Exclusão remove somente o registro selecionado.
   - Clicando no histórico abre edição.
   - Em Mov., somente a região do extrato é o scroll principal.

10. Perfil da conta
    - Cabeçalho, resumo, métricas e filtro ficam fora da lista rolável.
    - Somente o extrato da conta possui scroll interno.
    - Data "Até" inicia no dia atual.

11. Frases
    - 128 frases originais distribuídas por contexto:
      Entrada 16; Saída 16; Transferência 16; Rendimento 16;
      Aporte 16; Reserva 16; Objetivo 16; Edição 8; Neutras 8.
    - Histórico de 30 frases para reduzir repetição.
    - Nem todo lançamento exibe frase motivacional.

12. Sincronização
    - Automática ao abrir, se configurada e online.
    - Automática quando a conexão volta.
    - Não bloqueia a abertura do app.
    - Snapshot completo com revisão incremental.
    - Base Google Sheets separada recomendada.

LIMITAÇÃO DO AMBIENTE
---------------------
Foi tentada renderização visual automatizada com Chromium headless local.
O processo do navegador não concluiu de forma confiável neste ambiente (restrição do Chromium/DBus), portanto o QA NÃO marca como concluído um teste visual real de Safari/iPhone.

As três imagens de referência aprovadas estão incluídas em docs/ para comparação visual durante a publicação.
O teste final de acabamento deve ser feito no iPhone real após o primeiro deploy.
